# 内核与插件升级边界

## R11.3 当前结构

| 目录 | 用途与升级边界 |
| --- | --- |
| `core/<版本>/` | 原版 DeepSeek Harness 内核及其依赖；本版未修改内核，已有散列验证 |
| `launcher/`、`runtime/` | 自有启动适配和运行环境，独立于内核源码 |
| `extensions/` | 品牌、部署、钉钉适配、技能孵化器、PDF 等扩展及离线依赖 |
| `config/` | 部署模板、插件启用清单和组织默认配置（公开包不含组织凭据） |
| `data/` | 模型/RAG 的用户配置、会话、定时任务和机器人绑定等运行数据；不应由升级包覆盖 |
| `workspace/` | 用户工作文件，不应由升级包覆盖 |

浏览器恢复补丁以独立 bundle 启用 Playwright，并使用专门的增量迁移器补齐缺失接口定义、适配旧 `tools/browser_session.py`。这不放宽通用插件包的写入边界；已有接口连接配置保持不覆盖。详见[浏览器与接口补丁](BROWSER_API_PATCH.md)。

启动器通过 `config/app.json` 的 `coreVersion` 选择内核目录，并把扩展和部署补丁组合到运行时 profile。当前不修改上游内核源码，但自有扩展依赖内核的工具、设置页和技能接口，升级仍需兼容性验证。内核升级可能涉及 profile/数据格式迁移，不能承诺替换目录即可安全升级；应先备份配置和数据，在独立目录测试，再切换并保留回退路径。

Core/Plugins 是发行文件的划分，不表示所有自定义内容都在 Plugins 包：核心包还包含启动器、品牌/部署适配和配置模板。定时任务服务是内核自带的可选模块；新增 PDF/技能代码在扩展中。这两种边界须分开理解。

## 后续单独安装插件

同一内核及运行环境下，兼容插件可以独立交付，无需重新分发整个 APP。纯内网插件必须带齐依赖、OCR 数据等资源；不能依赖安装时 npm 下载。插件更新需同步启用清单、验证架构/接口兼容性，并退出、重启 APP；不应覆盖 `data/`、`workspace/` 或用户授权配置。

**原 R11.3 整套插件安装器**仍要求 APP 发行版本和平台一致，适用于首次安装原配插件。新增的[离线插件管理器](OFFLINE_PLUGIN_MANAGER.md)支持按内核兼容清单安装独立插件、升级同名插件、自动备份和回退，不要求 APP 发行编号相同。既有 R11.3 用户安装小型接入包后即可使用，不必重装整个 APP。

该机制已实现文件散列、运行环境与原生库架构校验，依赖检查、暂存替换、事务备份、回滚和中断恢复，并同步插件启用清单。插件更新不写模型/RAG配置、绑定、聊天、工作区或内核。仅复制文件夹仍不足以正确安装，请使用包含完整清单和依赖的离线包。历史已发布的两份 R11.3 APP 分包保持原内容，接入包和后续源码构建包含新管理机制。

## 为何拆成两个安装包

按组织使用限制，**内网钉钉只允许上传 500 MB 以内的文件**。R11.3 原完整安装包约 587 MB，因此拆为约 381 MB 的 Core 和约 207 MB 的 Plugins；每个文件均小于 500,000,000 字节。

GitHub Release 的上传资产只保留两个安装包。安装方法、校验值和交接说明放在发布正文及仓库文档；GitHub 自动生成的 Source code zip/tar.gz 不属于手动上传资产，标准发布页面会另外显示。
