### 未发布 — 变更审阅与回退轮次（2026-10-27）

- **新增**：右栏「变更」页，按轮次、手动确认检查点、轮次结束后手动修改三类时间线展示工作区检查点；文件行级红绿对比，单文件可回退/前进。二进制文件只标注类型、不展开行级比较，也不把字节计入 `+/-` 统计。
- **变更**：检查点改为工作区级共享，所有会话（含分叉会话）看到同一份时间线；轮次编号用 `roundId` 而不是会话内的 `turn`，多个会话同时运行时算同一轮，全部结束才封口。快照只做轮次边界，文件变更基准仍以手动确认的检查点为准。
- **新增**：轮次开始与结束各写一份快照（manifest 的 `phase` 为 `start`/`end`）。结束快照在 agent 转 `idle` 后捕获，用于把轮次结束后的手动修改单独归属，不再并入上一轮。
- **修复**：`roundId`/`phase` 未纳入 manifest 校验，读取时被丢弃，导致结束快照退化为普通快照、「对话结束」无法识别；同时移除 treeHash 相同即复用旧快照、不落盘的优化。
- **变更**：工作区正被其他会话写入时，单文件回退与整体回退返回 `WORKSPACE_IN_USE` 并提示，不再并发改写；读取当前文件内容时校验路径必须留在工作区内。
- **变更**：回退插件的 host id 不再读取系统指纹（受控机器上 `reg query MachineGuid` 可能不可用），改由启动器在数据目录生成并持久化 64 位十六进制 ID，经 `DSH_TURN_REWIND_HOST_ID` 注入；不经启动器直接运行时该插件拒绝工作。
- **变更**：系统未安装 Git 或不在 PATH 时按「不在任何仓库」处理，退回普通目录快照，不再让整条回退功能失败。
- **变更**：右栏「变更」页在挂载/切会话、页签由隐转显、手动刷新、操作完成后刷新，并在对话开始时（延时 1.5 秒）与结束时（延时 1.2 秒）自动刷新，避开快照尚未落盘的窗口。
- **变更**：页签开多后页签条可横向滚动。内核原本给条带设了 `scroll-behavior: smooth`，连续滚轮会反复打断缓动、速度不匀；这里覆盖为 `auto`，滚轮按 12px/帧匀速推进到目标位置（每格最多 60px），并把滚动条收窄到 2px、悬停才明显，减少占高。
- **验证**：Windows x64 实测结束快照落盘（`turn=6 phase=end round=2`）、轮次封口显示结束时间、轮次结束后的手动修改单独成条目；发送消息后 +2 秒显示「第 N 轮 · 进行中」、+17 秒自动封口；PNG 等二进制文件不再触发行级比较。`tsc` 对 16 个服务端源文件类型检查零错误。未运行 `npm test`、`scripts/check_source.py`，也未做麒麟平台回归。
- **发布状态**：仅源码与本地开发构建，未重建或替换安装包；与 GitHub R11.6 已发布资产无关。

## 1. 接手先看：R11.6与当前边界

目标是在纯内网麒麟 ARM64 上提供带图形界面的内网小智，同时提供 Windows x64 版。运行依赖随包提供，安装不要求访问 npm/PyPI，也不要求 sudo；模型和知识检索仍访问组织内已有的模型/RAG服务。

| 项目 | 当前状态 | 接手时注意 |
|---|---|---|
| 当前 APP / 内核 | R11.6 / DSH 0.2.1-rc.3 | 不直接修改官方内核 |
| 内网固定配置 | Internal 包内置模型、RAG、接口资料 | 不依赖旧APP，不执行首次配置或迁移 |
| Windows 桌面 | 已启动并验证页面加载 | x64，不适用 Windows ARM64 |
| 麒麟运行 | ARM64 隔离环境测试通过 | 实体麒麟桌面及组织服务仍需现场验收 |
| 独立插件更新 | 已有离线安装、升级、恢复和回退 | 不能直接复制任意插件目录当作安装 |
| 浏览器自动化 | Playwright 控制随包 Electron | 中广核本机浏览器接入尚未实现 |
| 敏感操作审批 | 内核审批、钉钉管理员验证已有基础 | 插件尚未统一强制真人审批 |

## 4. 界面和启动链路

```text
start.sh / start.cmd
  → launcher/supervisor.cjs
  → launcher/bootstrap.cjs
  → 校验插件状态、初始化Internal默认配置、生成运行时profile
  → 随包Node运行 dsh web --no-open
  → Electron加载本机认证页面
  → 插件贡献设置页、工具、知识检索和业务功能
```

主窗口与业务浏览器是两个用途：主窗口显示聊天/设置；业务浏览器由 Playwright 插件按需启动，用于用户登录业务系统。当前没有接入外部中广核浏览器。

配置按层合并：内核默认 → 部署覆盖 → 用户profile补丁。用户层应保留最终覆盖优先权。删除某项覆盖不代表禁用内置插件；需要明确 disabled，避免旧默认值回落。模型解密和提供者配置由启动适配完成，不把密钥写进Git。

Internal 默认配置首次启动复制到 data/config；已有用户文件不会被默认配置覆盖。这里的“固定”是预置服务配置，仍需能访问组织服务，并非将运行时文件锁定为只读。钉钉绑定和组织账号登录不属于可直接复用的固定模型/RAG配置。

## 5. 安装与首次验收

### 5.1 内网麒麟：无需迁移、无需配置模型/RAG

将匹配的 Internal Core、Internal Plugins 和合并脚本放在同一目录。普通用户执行：

```sh
sh 合并安装R11.6.sh "/data/内网小智R11.6"
sh "/data/内网小智R11.6/Neiwang-Xiaozhi-Kylin-ARM64-R11.6/start.sh"
```

目标目录必须不存在；两份 tar.gz 在麒麟端解压，保留权限和符号链接。不要用Windows展开目录逐文件拷贝。详细步骤见 [安装与使用](INSTALL.md)。

### 5.2 Windows / 公开包

Public 包不带组织模型/RAG配置。两份同版本ZIP解压到同一父目录后，在APP根目录执行：

```powershell
& .\runtime\node\node.exe .\plugin-pack\install.cjs
& .\配置模型.cmd
& .\配置RAG.cmd
& .\start.cmd
```

RAG仅在需要知识库时配置；公开包完整解压命令见 [安装与使用](INSTALL.md)。以上配置步骤不适用于已经预置的 Internal 交付版。

### 5.3 现场验收顺序

1. 核对两包版本、平台、类型和SHA256，确认Core及Plugins各小于500MB。
2. 启动主窗口，确认标题“内网小智”、首页“你说我做”、无左上角编辑菜单。
3. 向模型发普通测试问题；单独验证RAG检索，检查回答引用来源。
4. 在业务浏览器亲自登录，先测试只读页面和登记的只读接口。
5. 配置组织批准的钉钉机器人并绑定管理员；测试消息需要操作者明确授权。
6. 验证定时任务、插件列表和重启后的持久状态。关闭/休眠/关机不执行定时任务，不承诺补投递。

验收默认不修改真实表格、不提交审批、不自动发送测试消息。涉及真实业务写入时，先确定目标、范围和授权。

## 6. 常见故障与定位顺序

| 现象 | 优先检查 | 处理边界 |
|---|---|---|
| 麒麟窗口不启动 | 平台架构、Electron动态库、沙箱环境、启动错误文件 | 使用ldd定位；不默认加--no-sandbox绕过 |
| 界面重新连接 | 后台是否退出、端口占用、本机认证、浏览器控制台 | 不照搬旧版polyfill补丁进内核 |
| 模型不能回答 | 内网模型服务可达性、模型名称、配置完整性 | 不在聊天/日志贴密钥 |
| RAG未配置或无结果 | dify.enc是否初始化、RAG开关、服务地址可达、检索错误 | 失败/空结果不能作为知识证据 |
| 接口源列表为空 | 是否装Plugins、extensions/apis、是否误用Public包 | Public没有真实组织接口源是预期 |
| 钉钉Stream重连 | DNS、HTTPS/WSS可达、代理、组织网关、凭据验证 | 客户端消息同步不等于机器人API可达 |
| 浏览器业务登录失败 | 证书、代理、SSO、客户端证书、专用组件要求 | 目前尚无组织现场兼容验收 |
| 插件更新中断 | 事务状态、磁盘空间、用户修改冲突 | 先recover，不直接删锁或覆盖插件 |

已知诊断证据：用户麒麟报告中钉钉多个平台域名DNS返回 ENOTFOUND，获取token与Stream连接均失败。这说明当时网络解析链路失败，不能据此判断机器人密钥错误；需组织网络人员提供允许的解析/代理/API通路。报告本身和账号标识不上传公开仓库。

常用只读检查（APP根目录）：

```sh
uname -m
./runtime/node/bin/node --version
ldd launcher/electron/electron
ss -lnt
# 留意以下文件可能包含内部信息，提交前脱敏
ls data/config
```

不要把带token的启动URL、原始日志、Cookie、profile凭据或运行时认证文件发到GitHub。

## 7. 定制能力与实际边界

- 品牌：主标题32px、副标题18px，首页隐藏“预览版”；PDF内容预览功能保留。
- 提示词：SDK参数按需发现，保留安全上下文；R11.6 Windows测试系统字符51583→8635，ARM64为50447→8468；不是精确token测量。
- RAG：遵守开关，同聊天复用已有材料，知识正文视为参考数据；模型配置和RAG配置独立。
- Playwright：页面快照、iframe、填写、点击、滚动、拖拽、截图；密码由本人输入；未提供任意JS/Cookie导出工具。登记只读接口的会话桥接仅在工具内部使用。
- AI表格：插件具备读写命令，组织授权另行管理；写入先预览。新包工作区规则已更新，旧安装的用户规则仍需自行核对；统一真人审批尚未完成。
- 审批：内核具备ask审批、记录与失败拒绝；钉钉审批校验绑定管理员。浏览器/表格confirmed参数仍由调用方提供，尚未统一到不可绕过的真人审批。
- 技能孵化器与better-sidebar：离线依赖随插件包。PDF解析大师已移除，不再以它提供PDF/OCR工具；原生预览及已有通用文件工具独立保留。

## 8. 后续插件安装、升级与回退

关闭APP，在APP根目录用原用户执行：

```sh
sh 管理插件.sh check "/离线插件包目录"
sh 管理插件.sh install "/离线插件包目录"
sh 管理插件.sh list
# 更新失败或中断
sh 管理插件.sh recover
# 必要时回退最近一次插件事务
sh 管理插件.sh rollback
```

原配 plugin-pack 安装器用于首次初始化；增量包必须使用 plugin-package.json 格式，声明平台/内核兼容性和依赖。不能直接将初始Core/Plugins包当作增量插件包。

管理器更新插件与登记信息，不替换模型、RAG、绑定、workspace或core。后续插件自己的业务数据迁移需要独立兼容方案，代码回退不会撤销外部业务请求。详见 [开发与插件维护](DEVELOPMENT.md)。

## 10. 构建、公开发布及隐私边界

以下为开发者构建细节；源码仓库不包含全部平台运行时材料。纯离线重建前需单独准备已审核基线、平台原生依赖和组织私有输入。新接手同事不能仅克隆仓库就假定能立即完整重建安装包。

### 10.1 构建与私有输入

`scripts/build-r115-release.py` 从已校验的麒麟Public基线和现有Windows基线提取运行时资源，使用单独准备的0.2.1-rc.3官方内核材料替换旧core，组合侧边栏、技能、浏览器、提示词精简、品牌与插件管理工具。第三方版本/许可证见各扩展的package.json、lock、upstream.json和LICENSE。

```sh
# 只需设置一次本机路径；此清单被Git忽略，不填密钥内容
cp config/build.example.json config/build.local.json
# 修改本机路径后，检查并构建
python scripts/build-release.py --check
python scripts/build-release.py
```

“已审核麒麟Public基线”是组织在构建机保存的已验证公开安装归档，用于提供麒麟运行时、桌面资源和平台材料，不是名为“材料”的必备目录，也不等于历史源码。基线文件以SHA256锁定；新发行用新内核材料替换其中的旧内核，历史源码快照可以删除。

本地清单统一保存基线、两平台新内核材料、已预配置内网APP、Node和输出目录的路径。模型/RAG、接口文档和接口源从一个privateApp自动定位，不再逐项传八个命令行参数。私有参数的实际内容不进入仓库；历史R11.4入口已停用，当前入口为build-release.py。

构建前先用随包官方DWS CLI执行 `node scripts/generate_dws_contracts.mjs /平台/DWS可执行文件 extensions/@neiwang/dws-aitable/contracts.json`，确保生成27项完整命令Schema；该步骤只读取本地Schema。

三个私有输入只在组织内保管，不入 Git。构建不执行接口文档中的代码，不请求模型、RAG、钉钉或业务系统；只在内存中解密当前模型/RAG并按新安装密钥重新加密到 Internal 的 defaults。Windows 机器人绑定不作为麒麟的默认绑定，避免两个实例抢同一机器人；实际旧麒麟绑定通过原机迁移保留。

构建输出分离为：

```text
构建目录/
├─ Public/Neiwang-Xiaozhi-Kylin-ARM64-R11.6/
├─ Public/Neiwang-Xiaozhi-Win10-x64-R11.6/
└─ Internal/Neiwang-Xiaozhi-Kylin-ARM64-R11.6/
交付目录/
├─ GitHub/              两平台四个Public拆分包
└─ Send-to-Intranet/    仅供组织内传递的麒麟Internal两包
```

内网钉钉仅允许上传500MB以内文件，因此每个平台拆分 Core/Plugins。两包各含互不重叠的同一根目录成员，解压到同一个新父目录后执行插件安装器。不得拼接压缩字节流。命令及旧配置迁移见 [安装与使用](INSTALL.md)。初始组合包安装器仍按发行版本匹配；后续插件维护使用独立事务管理器。
